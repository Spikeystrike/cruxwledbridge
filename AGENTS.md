## Environment and commands
- Use `.venv\Scripts\python.exe`; do not repeatedly search for Python or install packages globally.
- Run `powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 Check` for imports and dependency validation.
- Run `powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 Test` for the full unittest suite, including the Node.js UI test. The helper supplies Node and project-local temporary storage. Do not accept a skipped UI test as a complete pass.
- In this Windows sandbox, `asyncio` hung in `socket._fallback_socketpair` even with mocked external HTTP requests. Run the test command with the tool's approved `require_escalated` mode when that sandbox restriction applies; extra filesystem grants do not fix it. The helper aborts after 120 seconds with a traceback instead of waiting indefinitely. Do not change application/test behavior to work around the sandbox.
- Run `powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 Setup` only when dependencies or the environment need setup. It uses `requirements.txt` plus `requirements-dev.lock.txt`. Package downloads need network access; do not repeatedly retry a denied network request.
- Run `powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 Run` for the foreground server at http://127.0.0.1:8000. It needs a configured `config/config.py`; the tests do not.
- For direct Python commands, set `TEMP` and `TMP` to the absolute project `.cache\tmp` path and `PIP_CACHE_DIR` to `.cache\pip`. Windows sandbox temporary directories were not writable during initial setup. Use `PYTHONUTF8=1` when running the tests directly.
- Python and Node fall back to the Codex runtimes under `%USERPROFILE%\.cache\codex-runtimes\codex-primary-runtime\dependencies`. `dev.ps1` also accepts explicit `-Python` (setup) and `-Node` (tests) paths.

## Code map
- `main.py`: API routes, SQLAlchemy models, settings, diagnostics, lighting and MoonBoard persistence.
- `utils.py`: grid geometry, logical/physical LED mapping, WLED requests and effects.
- `config_loader.py`, `config/config.example.py`: configuration loading and documented settings.
- `templates/*.py`: HTML/CSS/JavaScript generated by Python, including wall and virtual mapping UIs.
- `tests/test_utils.py`: backend, geometry, configuration and generated-page regression tests.
- `tests/test_wallselector_ui.py`, `tests/wallselector_manual.cjs`: Node-based UI behavior test.
- `docker-compose*.yml`, `Dockerfile`: production deployment; `dev.ps1` is the local entry point.
